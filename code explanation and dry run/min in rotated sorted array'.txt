Bilkul bhai ❤️ Is baar ekdum zero se karte hain. Ye question pehle wale rotated-array search se thoda different hai, isliye confusion hona normal hai.

Question: Minimum in Rotated Sorted Array

Example:

l = [4,5,6,7,0,1,2]

Hume minimum value chahiye:

0

Aur hum ye code use kar rahe hain:

l = [4,5,6,7,0,1,2]

left = 0
right = len(l)-1

while left < right:
    mid = (left+right)//2

    if l[mid] > l[right]:
        left = mid+1
    else:
        right = mid

print(l[left])
🧠 Sabse pehle: ye code kar kya raha hai?

Ye minimum ko directly find nahi kar raha.

Ye actually kya kar raha hai?

left aur right ko baar-baar adjust karke minimum ke index par le ja raha hai.

End me:

left == right

aur wahi index minimum ka hota hai.

Phir:

print(l[left])

se minimum value mil jaati hai.

🔥 Sabse important observation

Array:

[4,5,6,7,0,1,2]

Normal sorted array hota:

[0,1,2,4,5,6,7]

Rotation ki wajah se:

[4,5,6,7 | 0,1,2]
          ↑
       minimum

Minimum ke around array ka order break hua hai.

Hume isi break point ko find karna hai.

🧠 Ab sabse important conceptual part

Tumhe ye do cases interview ke liye yaad rakhne hain:

CASE 1
l[mid] > l[right]

Example:

7 > 2

Matlab:

Minimum mid ke right me hai.

Therefore:

left = mid + 1
CASE 2
l[mid] <= l[right]

Example:

1 <= 2

Matlab:

Minimum mid ya mid ke left me hai.

Therefore:

right = mid

mid - 1 nahi, because mid itself could be minimum.

🤯 Tumhe right = mid ajeeb lag sakta hai

Isko ek example se pakdo:

[1,2,3,4,5]
    ↑
   mid

Maan lo mid par 1 aa gaya.

Agar tum:

right = mid - 1

kar doge, to 1 ko hi search se hata diya.

❌ Answer miss.

Lekin:

right = mid

karoge, to mid abhi search space me safe hai.

✅

Interview me internal working kaise explain karna hai?

Agar interviewer bole:

"Explain your approach."

Tum bolna:

"Because the array is a rotated sorted array, the minimum element is at the point where the sorted order breaks. I use binary search to locate that point. At every iteration, I compare the middle element with the rightmost element. If the middle element is greater than the rightmost element, the minimum must lie to the right of mid, so I move left to mid plus one. Otherwise, the minimum lies at mid or to its left, so I move right to mid. I continue until left and right converge. At that point, left is the index of the minimum element."

🔥 Ye interview-quality explanation hai.

Complexity

Har iteration me search space roughly half ho raha hai.

So:

Time Complexity: O(log n)

Koi extra array/set nahi banaya:

Space Complexity: O(1)

❤️ Aur ek final memory trick

Isko bas 2 arrows ki tarah yaad rakh:

        mid > right
             ↓
       minimum RIGHT
             ↓
       left = mid + 1

Aur:

        mid <= right
             ↓
       minimum LEFT/MID
             ↓
         right = mid

Then:

left == right
     ↓
minimum mil gaya
     ↓
l[left]

Previous question se confuse mat karna:

Search in Rotated Array → sorted half + target range
Minimum in Rotated Array → mid vs right
